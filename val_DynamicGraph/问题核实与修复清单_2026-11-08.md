## 1. 兴趣摘要上传时点（F7）

### 核实

- **论文原文**（中期报告 L130 / `tools/edit_mid_report.py` L224）：
  「对于参与客户端 i∈C_t，**客户端完成本地训练后**上传当前短期兴趣摘要，服务器更新其缓存」。
- **旧实现**（`feddieg_core/federated.py` 训练循环）：
  `last_summary = current_s_i.detach()` 取的是**最后一个 epoch 前向**（`optimizer.step()` 之前）的 `s_i`；
  上传发生在循环之后（L316），但用的仍是这个"训练前"的摘要。
- **A/B 主程序同样如此**：`FedDIEG.py` L344–374 与 `exp_01/.../run_exp01_movielens_aligned.py` L1418–1442
  都是 `final_s_i = current_s_i` 后再 `optimizer.step()`。所以旧代码是"忠实复刻参考实现"，
  但**与论文文字不一致** —— 属于实现与论文的偏差，不是我们审计时引入的 bug。
- **实测**（探针，lr=0.5、单客户端）：
  `uploaded == 训练前的 forward`（max|Δ| = 0.0）；
  `uploaded == 训练后的 forward` 为 False（max|Δ| = 2.60）。

### 修改

`federated.py`：在本地 epoch 循环结束后，用**更新后的参数**重算一次摘要：

```python
if last_summary is not None:            # 论文口径：训练完成后重算
    self.worker.eval()                  # 关 dropout，保证上传摘要可复现
    with torch.no_grad():
        _, s_after = self.worker(seq, nbr_sum, nbr_w, cfg.graph_mix)
    last_summary = s_after.squeeze(0).detach()
    # 若本轮有邻居，同步重算 delta（供下一轮 L_struct 使用）
```

- 邻居摘要仍用**本轮开始时**的缓存（与论文一致：本地训练期间邻居固定）。
- 上传摘要同时写入 `client_prev_summary`（下一轮 `L_temp` 的 `prev_s`）。
- **设计选择**：重算用 `eval()`（关闭 dropout）→ 上传结果确定、可复现；代价是与训练前向的 dropout 流不同。
  若希望严格"训练态"重算，把 `eval()` 去掉即可（一行）。

### 影响

改变摘要 → 图边权 → 后续轮的邻居聚合；同时改变 `prev_s`（L_temp）与 `prev_delta`（L_struct）。
**训练过程改变，受影响实验必须重跑。**

## 2. Top-K 候选不足（F9，未复现）

### 核实

用合成图逐项验证（`N ∈ {2,3,5}`、`K=4`、`min_sim=0.9` 无候选、`pool<K`、`graph_state=topk`）：

```
N=2 K=4 -> ids [[1],[0]]                       权重和 [1.0, 1.0]   无重复
N=3 K=4 -> ids [[2,1],[2,0],[1,0]]             权重和 [1.0, 1.0, 1.0]
N=5 K=4 -> 每行 4 个不同邻居                     权重和 [1.0×5]
min_sim=0.9 -> 全部 -1（无候选）                 权重和 [0.0×5]
graph_state=topk -> 同上                         无重复、和=1
```

原因：审计修复 F2 已经把无效槽位写成 `-1`（`new_ids = where(keep, …, -1)`），`keep` 掩码只对合法槽位做
softmax，`gather` 再把无效槽位权重清零。所以"重复填同一邻居 / 权重和 >1"在当前实现下不存在。

### 处理

**不改代码**，补两条回归断言（B12，`N=2` 与 `N=3` 两种候选不足场景），防止以后回退。

## 3. 负采样与时间切分（F8）

### 3c 时间切分本身：✅ 无问题

- `full_df` 先按 `timestamp` 排序；窗口 = 连续时间片（`window_bounds`）。
- 训练序列 = `history_seq[:val_pos]`（**不含本窗口 val/test**），`seq/pos` 由该前缀按因果方式构造。
- 评测候选只在该窗口评测时使用（`sample_candidates` 排除 `test_histories + test_item`），不进入训练。

### 3a 负采样排除集：✅ 成立（利用未来信息）

- **旧实现**：`history_sets_from_frame` = `full_df.iloc[:end_w]`，即"截至窗口末的完整历史"，
  包含本窗口的 **val 与 test** 物品。
- **实测**（ML-1M，5 个窗口）：旧排除集**包含每个评测用户的 test 物品**（1429/1429、1421/1421、
  1763/1763、1547/1547、1738/1738 = **100%**）；因果口径为 **0**。
- 平均排除集大小：旧 139.9/168.2/159.8/162.3/252.4 → 因果 137.9/166.2/157.8/160.3/250.4（各少 2，即 val+test）。

### 3b 回退路径：✅ 成立

- **旧实现**：`picked = np.where(valid, picked, cand[:, 0])` —— 若 32 次抽样都落在历史里，
  直接取第 1 个候选，**它可能正是历史物品或正样本** → 标签噪声。
- **参考实现**：`dataset_01.Seq_TrainDataset` 用 `while True` 重采样，永不回退到历史物品。

### 修改

- 新增 `causal_history_sets(...)`：按 exp_02 的切分规则截断——有评测记录的用户去掉最后 2 个（val/test），
  其余用户去掉最后 1 个；`load_client_windows` 改用它。
- `sample_negatives` 的回退改为**确定性线性探测**（从随机起点扫描，保证不在历史、不等于目标）。
- 保留 `training_history_from_fast`（seq∪pos 的保守近似）作为工具函数与测试用。

### 影响

负样本集合改变（排除集少 2 个物品；val/test 物品现在可以合法地作为负样本）。
**训练过程改变**（幅度应很小：每条负样本只有一个取值，test 物品被抽中的概率约 `L/num_items`）。

## 6. 修复前后回归（ML-1M，seed 42）

基线 = `results/raw_phase2b`（ECR v2、**未含** F7/F8）；新 = `results/raw_fix1`（含 F7/F8）。

| 臂 | 窗口级 NDCG 旧 → 新 | Δ | 末窗 NDCG 旧 → 新 | Δ | neighbor_lift 旧 → 新 |
|---|---|---|---|---|---|
| nograph | 0.2383 → 0.2379 | −0.0004 | 0.2346 → 0.2345 | −0.0000 | — |
| static | 0.2349 → 0.2340 | −0.0009 | 0.2281 → 0.2264 | −0.0017 | 0.722 → 0.763 |

**逐窗口 Δ（new − old）**：

```
nograph  [-0.0003, -0.0001, -0.0003, -0.0005, -0.0003]
static   [-0.0004, +0.0002, -0.0003, -0.0005, -0.0007]
periodic [-0.0004, +0.0001, -0.0004, +0.0013, +0.0016]
dynamic  [-0.0002, +0.0005, +0.0008, +0.0008, +0.0001]
```

**解读**

1. **nograph 也变了（−0.0004）** —— 它没有图，变化只能来自 F8（负采样）。这正好证明 F8 真的改变了训练。
2. **幅度 ≤ 0.0009**，小于或接近 3 个种子之间的 sd（约 0.001–0.002），所以**结论方向不受影响**：
   排序仍是 nograph < static < periodic < dynamic；③（dynamic−nograph）从 +0.0109 → +0.0119，
   ⑤（dynamic−periodic）从 +0.0015 → +0.0020（seed 42）。
3. **结构指标变化比 NDCG 明显**：邻居质量 lift 全部上升（+0.04~0.06）；dynamic 的 `avg_ecr` 0.1728 → 0.1248
   （图更"稳"）——说明 F7 让摘要更收敛、边变化更平滑，这类指标必须用新数据重算。
4. **耗时**：同一批 4 臂 27:48 → **31 分钟**（+11%），来自每客户端每轮多一次前向。

> 单种子只能看方向，不能做显著性；正式结论要等阶段 4 的 5 种子。

## 9. 遗留与注意

1. **F7 的重算用 eval 模式**（关 dropout）。这是为了上传摘要确定可复现；若你要求"训练态"，删掉 `eval()` 一行即可，但那样同一份数据两次上传的摘要会有 dropout 噪声。
2. **F8 的排除集口径**是"截至训练截止点的全部历史"（有评测去最后 2 个、其余去 1 个），与 A/B 的
   `Seq_TrainDataset.user_items_set` 对齐；`training_history_from_fast`（仅 seq∪pos）是受 `max_len` 截断的保守近似，只用于测试。
3. **ECR 旧数据**（`results/raw`）是 legacy 定义，不能与新数据混比；新 run 带 `ecr_def=v2_empty_to_full`。
4. 单种子回归的 Δ 只能看方向；5 种子后才能判断 F7/F8 是否让 ⑤ 等小效应变大或变小。
