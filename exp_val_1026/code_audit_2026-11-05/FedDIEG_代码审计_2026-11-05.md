### 2.2 论文声称的算法（原文，取自 `tools/edit_mid_report.py`）

```text
L217  … 设第 t 轮参与训练的客户端集合为 C_t，其中 |C_t| = max(⌊C·N⌋, 1)。
      服务器端为每个客户端维护最新可用兴趣摘要缓存，用于支持部分参与条件下的异步图演化。
L224  对于参与客户端 i∈C_t，客户端完成本地训练后上传当前短期兴趣摘要，服务器更新其缓存；
      对于非参与客户端 i∉C_t，服务器不主动推断其当前兴趣，而是沿用上一轮最新可用摘要：
          s̄_i^t = s_i^t,      i ∈ C_t
          s̄_i^t = s̄_i^{t-1},  i ∉ C_t
L242  服务器基于缓存摘要而非所有客户端的当前轮表示计算候选边权，并用活跃节点掩码过滤：
          a_i^t = 1[ ||s̄_i^t|| > ε ]
          Δe_ij^t = a_i^t · a_j^t · max(0, cos(s̄_i^t, s̄_j^t)),  i ≠ j
L274  随后，服务器对每个活跃节点的候选边进行 Top-K 筛选，并采用指数移动平均进行平滑更新：
          e_ij^(t+1) = ρ · e_ij^(t) + (1-ρ) · Δe_ij^t
L285  其中 ρ 为历史拓扑保留系数。… 对于已有历史缓存但本轮未参与的客户端，
      其边权由缓存摘要参与服务器端异步更新。
```

关键点：**论文里 `e_ij` 与 `Δe_ij` 都是 `max(0,cos)` 量纲**，EMA 与阈值在同一量纲上，且 `e_ij` 是**对全部点对**定义的。下面的 §3 全部围绕这两点展开。

## 3. 四个问题的逐项核实

### 3.1 问题一：EMA 混用归一化边权与原始余弦（`val01`）

**判定：成立，是真实缺陷。**

`val01_run_staleness.py` 的 `update_graph`：

```python
# L260-L282
if edge_ema > 0:
    prev = torch.zeros_like(sim)
    ...
    for neighbor, weight in zip(neighbors_cpu[user], weights_cpu[user]):   # weight 来自 graph_weights
        ...
        flat_vals.append(float(weight))
    prev[row_t, col_t] = ...            # ← prev 里装的是"和为 1 的相对权重"
    blended = (1.0 - edge_ema) * sim + edge_ema * prev    # ← sim 是原始余弦
    has_prev[row_t] = True
    sim = torch.where(has_prev.unsqueeze(1), blended, sim)
```

- `weights_cpu = graph_weights.tolist()`（L248），而 `graph_weights` 在 L296–L299 已经被 `new_weights = [v / total ...]` 归一化（每行和为 1），K=10 时典型值 `1/K = 0.10`。
- `sim` 是 `norm_bank` 的余弦再 `clamp_min(0)`（L257），典型值 0.3–0.5（具体量级取决于摘要分布，见下面 (b)）。
- 于是一次"EMA"实际是 `0.2×0.30 + 0.8×0.10` 这种**跨量纲相加**。

更严重的是**阈值也作用在混合值上**（L293 `if v >= min_sim`，`min_sim=0.20`）：

| ρ | `blended = (1-ρ)·0.30 + ρ·0.10` | 是否过 `min_sim=0.20` |
|---|---|---|
| 0.0 | 0.300 | 保留 |
| 0.5 | 0.200 | 勉强保留 |
| **0.8（`val01` 默认）** | **0.140** | **被丢弃** |
| 0.95 | 0.110 | 被丢弃 |

即：**`val01` 在 ρ=0.8 下，凡是历史分量占到主导的边都会被阈值剪掉**，图不是"被平滑"，而是"被削稀"。这与论文"ρ 越大图越稳"的语义完全相反。

还有一个连带效应（L280–L282）：`has_prev` 是**整行**级别。一行只要有任意一条历史邻居还在候选池里，`sim` 就整行换成 `blended`；对那些原本没有历史的候选，`prev=0`，其值变成 `(1-ρ)·sim`。配合 L293 的阈值，`(1-ρ)·sim ≥ 0.20` 等价于

```
ρ=0.5 → sim ≥ 0.40 ；  ρ=0.8 → sim ≥ 1.00 ；  ρ=0.95 → sim ≥ 4.00
```

**ρ=0.8 时新边要进来需要余弦 ≥ 1.0（余弦的上确界），ρ=0.95 时需要 4.0。也就是说在 `val01` 的默认配置下，新邻居在数学上不可能进入 Top-K。** 这就是"图冻结"在 `val01` 里的直接来源。

复现：`audit_repro.py` 的 C 段（实测 `graph_weights` 每行 `sum=1.0000`，而 `sim` 是余弦；并给出上面的阈值表）。

**(b) 直接后果：`val01` 的图在第 1 轮之后就由"余弦量级"而不是"ρ"决定命运。**

保存一条边需要 `(1-ρ)·sim + ρ·w ≥ min_sim`，即

```
sim ≥ (min_sim − ρ·w) / (1 − ρ)
```

其中 `w` 是归一化后的相对权重（行和为 1）。`w` 不是常数：刚 warm start 重建时 `w ≈ 1/K = 0.10~0.125`，边越少 `w` 越大。取 `w = 1/K = 0.10`、`min_sim = 0.20`：

| ρ | 保存一条边所需的余弦下界 |
|---|---|
| 0.5 | 0.30 |
| **0.8** | **0.60** |
| 0.95 | 2.10（余弦上确界为 1 ⇒ 永远存不下任何边） |

取重建瞬间的 `w = 0.125`（K=10 时最大值）则 ρ=0.8 的下界降到 0.50。**也就是说 ρ=0.8 时"最强的那条边能不能活下来"取决于它的余弦是否越过 0.50–0.60 这个窄带**——而这恰好是真实摘要余弦所在的量级。图因此处在一个临界状态：要么冻结，要么每两轮被清零一次。

用真实的 `val01.update_graph` 跑合成数据（4 个兴趣簇、簇内余弦 0.33–0.50、K=10、min_sim=0.20、每轮更新全部用户）：

```
rho=0.0   -> 每行稳定保留 10.0 条边，ECR=0.000
rho=0.5   -> 每行稳定保留  7.7 条边，ECR=0.000
rho=0.8   -> 周期 2 振荡：奇数轮 10 条边、偶数轮 0 条边，ECR 在 0.795/0.000 之间跳
rho=0.95  -> 同上（0 条边那一相更彻底）
```

轨迹（用户 0，ρ=0.8，K=10）：

```
r1: 10 条边  w=[0.125,0.111,0.108,0.104]   # warm start
r2:  0 条边  w=[0,0,0,0]                    # 0.2×0.497 + 0.8×0.125 = 0.199 < 0.20，整行被阈值清空
r3: 10 条边  w=[0.125,...]                  # mask=False -> old=set() -> 又走 warm start
r4:  0 条边  ...
```

复现：`audit_val01_gate.py`（输出见 `audit_output_2026-11-05.log` 的 F 段）。

两种情况都是错的，只是错法不同：

- **`sim < 0.6` 时**：图每两轮被整体清空一次，GNN 每隔一轮就完全没有邻居输入。这不是"平滑"，是"开关"。
- **`sim > 0.6` 时**（`val01` 已产出运行的现象，ECR≈0.005–0.02）：边刚好卡在 0.20 的门槛上方，看起来"稳定"，实际是**行数被压到最少、且几乎不再变化**。此时"ρ 越大越平滑"无从体现，因为阈值已经把可变空间磨掉了。

无论落在哪一相，**结论"ρ 控制历史保留强度"在这个实现里都不成立**——真正的控制变量是 `(min_sim − ρ·w)/(1−ρ)` 与余弦量级的相对关系，而它与"历史保留强度"没有对应关系。

### 3.2 问题二：无效候选没有标 `-1`（`val02` / `val03`）

**判定：成立，是真实缺陷，而且已经污染了已产出结果里的指标。**

```python
# val02_run_ema.py L456-L478
cand_gated = torch.where(exists, cand, torch.full_like(cand, -1e9))
top_values, top_positions = torch.topk(cand_gated, k, dim=1)
new_ids = active[top_positions]                    # ← 被 -1e9 屏蔽的槽位，仍然映射成一个合法 user id
keep = top_values > -1e8                           # ← 有效性只记在 keep 里
...
graph_neighbors[block_users] = new_ids             # ← 直接写回，没有 where(keep, new_ids, -1)
```

`new_ids` 全部来自 `topk` 的下标，**永远 ≥ 0**。于是 `graph_neighbors` 里不会出现 `-1`。

危害有三条，全部已在下游代码里兑现：

1. **`graph_batch`**（L356–L361）`summary_bank[neighbors.clamp_min(0)]` 取的是被判无效邻居的摘要——因为 `weights * mask.float()` 把这几个槽的权重乘成 0，前向暂时无害。
2. **`CohortEdgeProbe.probe`**（`val02` L625）`n_valid = (nbr >= 0).float().sum(dim=1)`、L670–L676 的 turnover Jaccard 都用 `>= 0` 判有效 ⇒ **伪 id 被统计成真实邻居**。
3. **`update_graph` 自己的 ECR**（L467–L471）`old_sets = (old_ids >= 0) & mask` ⇒ 旧集合恒为满 K，ECR 的分母被稀释。

**已产出结果里的直接证据**：`results/raw/movielens-1m/rho0.80/seed_42/val02_user_round_metrics.csv` 里 7860 行、**`n_neighbors` 全部等于 10.0**。`min_sim=0.20` 的阈值在 MovieLens 上不可能让每个用户每轮都恰好凑满 10 条边，所以这个"恒为 10"只能是伪 id 撑起来的。

对照：`val01` 的实现是**正确**的（L303–L304 `ids_nested.append(new_ids + [-1] * pad)`），说明这是 `val02`/`val03` 重写 `update_graph` 时新引入的回归。

复现：`audit_repro.py` 的 B 段（把 `min_sim` 设成 2.0 使任何候选都不该存在，实测 `graph_neighbors` 仍然全是 `[0,1,2]`，24/24 个槽位 `>=0`）。

### 3.3 问题三：`scatter_` 覆盖有效历史边权（`val02` / `val03`）

**判定：成立，是真缺陷；但当前被 3.2 掩盖，属于"潜伏缺陷"——单独修 3.2 会让它立刻变成高频故障。**

```python
# val02_run_ema.py L425-L436
old_ids = graph_neighbors[block_users]                  # (B, k)，可能含 -1
old_col = active_slot[old_ids.clamp_min(0)]             # ← -1 被钳到 user 0 的列
has_prev = (old_ids >= 0) & (old_col >= 0) & graph_mask[block_users].unsqueeze(1)
if rho > 0.0:
    prev = torch.zeros((rows, num_active), ...)
    prev = prev.scatter_(1, old_col.clamp_min(0), old_weights * has_prev)      # ← 写 0
    prev_mask = prev_mask.scatter_(1, old_col.clamp_min(0), has_prev.float())  # ← 也写 0
```

两个问题叠在同一个 `scatter_` 上：

- **`-1` 被钳到列 0**。`old_ids = -1` → `clamp_min(0)` → 索引 `user 0`；若 `active_slot[0] == -1` 再 `clamp_min(0)` → 索引列 0。于是 padding 槽位会**写到某个真实候选的列上**。
- **重复索引会覆盖**。`src` 里 padding 位置的取值是 `old_weights * has_prev = 0`。如果该行的旧邻居里**恰好包含** `user 0`（或列 0 对应的那个用户），`scatter_` 的索引 `[col_of_user0, ..., col_of_user0]` 就出现重复，**后写的 0 覆盖掉真实历史值**，`prev_mask` 同列也被写成 0 ⇒ 该候选被当作"全新边"。

实测（`audit_repro.py` A 段，同一场景只差是否存在一个 `-1` 槽位）：

```
含 -1 padding 槽 : 用户1 的 smooth = [0.32, 0.159, 0.0696]   ← 用户0 的历史被抹成 0.0696 = 0.2×cos
无 padding（对照）: 用户1 的 smooth = [0.4696, 0.32, 0.159]   ← 0.8×0.50 + 0.2×0.348 = 0.4696（正确）
```

**为什么现在没炸**：3.2 让 `graph_neighbors` 在第一轮之后就再也不含 `-1`（全被伪 id 填满），`has_prev` 恒为真，`scatter_` 的 `-1 → 0` 通道根本不会被用到。所以

> **修复顺序必须是先 3.3 再 3.2。** 如果只把无效槽位改成 `-1`，每个"有效邻居不足 K 条"的用户行都会开始走 `-1 → col 0` 的路径，`scatter_` 覆盖会从"潜伏"变成"每轮都对某个固定候选生效"。

顺带一个推论：因为 `has_prev` 恒为真，`row_has_prev`（L446）也恒为真，于是**"首次建立邻居时 warm start" 这个兜底分支（L447）在第二轮之后就再也不会触发**，所有新候选都被强制按 `(1-ρ)·sim` 起步。这条和 §3.4 是同一个病灶。

### 3.4 问题四：新边初始化 ×`(1-ρ)` —— 算法设计还是实现缺陷？

**判定：`(1-ρ)` 本身是论文公式的正确落地（不是编程错误）；但"图冻结"不是公式的性质，而是"EMA 状态只保存当前 Top-K"这个实现选择造成的。所以结论是：设计没错，实现错了。**

拆成三步说清。

**(a) `(1-ρ)` 从哪来——它是公式而非笔误。**
论文 `e^(t+1)_ij = ρ e^(t)_ij + (1-ρ) Δe^t_ij`，若一对点此前没有边（`e^(0)_ij = 0`），递推解就是

```
e^(t)_ij = (1-ρ) Δe · Σ_{i<t} ρ^i  →  Δe · (1 - ρ^t)
```

所以 `new_edge_init="ema"`（`val02` L442–L443 `init_value = (1.0 - rho) * sim`）**忠实于公式**。`val01` 的注释（L235–L236）把它说成"原实现的缺陷"，这个说法本身不准确。

**(b) 单纯的 `(1-ρ)` 只会让新边"慢"几轮，不会让新边"永远进不来"。**
如果 Δe 恒定，`(1-ρ)·Δe·(1-ρ^t) → Δe`，ρ=0.8 时约 11 轮到 90%，ρ=0.95 时约 45 轮（见 `audit_repro.py` D 段）。这属于"适应慢"，是可接受的 EMA 语义。

**(c) 真正致命的是 Top-K 截断把非 Top-K 边的 EMA 状态扔了。**
代码里 EMA 状态是 `smooth_state`，形状 `(num_users, K)`（`val02` L719、`val03` L959），每轮被**整体覆盖**成"新 Top-K 的取值"（L478）。于是：

```
旧边：值 ≈ Δe_old（已收敛）
新边：每轮都从 (1-ρ)·Δe_new 起步（历史被丢弃，从头再来）
新边要挤进 Top-K，必须满足 (1-ρ)·Δe_new > Δe_old
            ⇒ Δe_new / Δe_old > 1/(1-ρ)
```

| ρ | 新边需要的余弦**倍数**优势 |
|---|---|
| 0.5 | 2.0× |
| 0.8 | 5.0× |
| 0.95 | 20× |

余弦相似度的取值范围是 `[min_sim, 1]`，真实数据里第 5 名与第 15 名邻居的余弦差通常只有百分之几到十几个百分点。**所以 2× 都极少出现，5×/20× 在数学上不可能。Top-K 成员集合一旦固定就永久不再变化。**

`audit_repro.py` D 段用真实函数验证了这一点（旧边 cos=0.70，新边 cos=0.90，高 29%）：

```
new_edge_init=ema   rho=0.0  -> Top-2 = [3,4]  换成新邻居
new_edge_init=ema   rho=0.5  -> Top-2 = [1,2]  仍被旧邻居占住（图冻结）
new_edge_init=ema   rho=0.8  -> Top-2 = [1,2]
new_edge_init=ema   rho=0.95 -> Top-2 = [1,2]
```

**(d) 判定实验：同一公式、同一场景，只改"状态存在哪里"。**
`audit_freeze_origin.py` 用受控相似度矩阵（新邻居只比旧邻居高 24%，即真实量级）跑 120 轮，第 31 轮让 10 个用户漂移：

```
  rho    变体        切换前ECR  切换轮ECR  切换后10轮ECR  R+10新邻居占比  R+40    R+100
  0.0    truncated   0.03333    0.30947    0.00000        1.000            1.000   1.000
  0.0    full        0.03333    0.30947    0.00000        1.000            1.000   1.000
  0.5    truncated   0.03333    0.00000    0.00000        0.000            0.000   0.000
  0.5    full        0.03449    0.10362    0.00833        1.000            1.000   1.000
  0.8    truncated   0.03333    0.00000    0.00000        0.000            0.000   0.000
  0.8    full        0.03359    0.10513    0.00833        1.000            1.000   1.000
  0.95   truncated   0.03333    0.00000    0.00000        0.000            0.000   0.000
  0.95   full        0.03369    0.10469    0.00061        0.000            1.000   1.000
```

- `truncated`（= 现在的 `val02`/`val03`）：ρ>0 时漂移用户的邻居**一个都不换**，ECR 在切换轮直接是 0。
- `full`（= 论文公式字面实现，保留 N×N 状态）：同样的 ρ，新邻居在 `O(1/(1-ρ))` 轮内完全替换旧邻居。

**结论：`(1-ρ)` 初始化不是 bug；`smooth_state` 只存 Top-K 是 bug。** 修法见 §6 的 P1-1。

**这直接解释了已有结果里的一个"异常"**：`val02` 各 ρ 的 `avg_ecr`（3 个种子均值）是

```
rho=0.00  0.45579      ← 完全不同的代码分支（cand = sim，无历史）
rho=0.50  0.00189      ← 比 ρ=0 小 240 倍
rho=0.80  0.00012
rho=0.95  0.00011
```

ρ=0 与 ρ=0.5 差 240 倍、ρ=0.5 与 ρ=0.95 只差 17 倍，这个"断崖"不是 EMA 的连续行为，而是 `cand = sim` 分支 vs `(1-ρ)` 分支的差别；ρ≥0.5 的三个点实际上测的都是同一个"冻结"状态。**因此 `val02` 的 ρ 扫描并没有测到"平滑强度"这个自变量，而是测了"图有没有被冻结"这个二元状态。**（`val02` 报告里"ρ 越大恢复越慢"的说法需要按这一条重写。）

## 4. 最重要的一条：联邦训练协议核实

### 4.1 事实：三条验证实验都不是联邦训练

`val01`、`val02`、`val03` 的 `run_single` 结构完全一致：

```python
# val02_run_ema.py L704-L705
model = FedDIEGModel(windows[0].num_items, cfg).to(device)      # ① 只创建 1 个模型
optimizer = optim.Adam(model.parameters(), lr=cfg.lr, ...)      # ② 只创建 1 个优化器

# L750-L814  每一轮
sampled = schedule[global_round - 1]                            # 采样"客户端"
for _ in range(cfg.local_epochs):
    shuffled = sampled[randperm(...)]
    for users in batched_indices(shuffled, cfg.microbatch_size):
        feats, short_summary = model(seq, neighbors, weights, gmask)
        loss = rec_loss + lambda_temp*temp_loss + lambda_struct*struct_loss
        loss.backward()
        optimizer.step()                                        # ③ 直接改共享参数
        summary_bank[users] = ...                               # ④ 只有摘要是"服务器状态"
```

`val01` 同构（L508–L509、L592–L651），`val03` 同构（L945–L946、L994–L1066）。

对照论文的联邦协议，缺的东西是**全部**：

| 论文协议要素 | 代码里是否存在 | 说明 |
|---|---|---|
| 每轮采样 `m = max(⌊C·N⌋,1)` 个客户端 | ⚠️ 形式上存在 | `schedule[round]`，但只是"这一轮用哪些用户的数据" |
| 客户端**下载**全局模型副本 | ❌ | 没有副本，直接改 `model` 本身 |
| 客户端在**本地数据**上做 `E` 步本地训练 | ❌ | `local_epochs` 只在**已采样集合**上多扫一遍，此时共享参数早已被前一个 microbatch 改过 |
| 客户端**上传**更新后的参数 | ❌ | 无 |
| 服务器**聚合**客户端参数（FedAvg） | ❌ | 无。服务器只聚合"兴趣摘要"和"图" |
| 聚合权重 / 个性化层 | ❌ | 无 |

**语义后果（这才是必须写进报告的）**

1. **"参与率"的含义变了。** 真 FedAvg 里，未参与客户端 = 本轮"模型不更新、数据不可见"；这里未参与客户端 = "这一轮它的样本没被采进 minibatch"。前者造成的是**模型侧陈旧**（客户端本地模型版本落后），后者只是**数据采样**。`val01` 的整个"客户端参与率 → 性能"结论因此只覆盖了后者。
2. **同一轮内客户端不再同起点。** 第 1 个 microbatch 的梯度算在 `θ_t` 上，最后一个算在 `θ_t + 12 步` 之后。真 FedAvg 中同一轮所有客户端都从同一个 `θ_t` 出发。
3. **`local_epochs` 参数失效。** 它现在是"把同一批数据再扫一遍"，不是"本地多步"。想用 `E=5` 模拟客户端本地训练是做不到的。
4. **`microbatch_size` 变成了"客户端数"。** `val02` 的 `participation_rate=1.0`、6040 用户、`microbatch_size=512` ⇒ 一轮只有 12 次参数更新；`val01` 的 `p=0.1`、604 用户 ⇒ 一轮 2 次。所谓"120 轮/窗口"其实只有 240 次 minibatch 更新。
5. **不存在"客户端模型漂移"这一现象**，而 FedAvg 里它恰恰是与"客户端长期不参与"最相关的失效机制。所以"陈旧是否影响推荐质量"这个问题在 C 版实现里**只可能通过摘要-图这条通路显现**，另一条更主要的通路被结构性抹掉了。

### 4.3 判定

- **"实验脚本里没有客户端本地训练与服务器聚合"——完全成立。**
- **"完整主程序是否实现了论文协议"——实现了，但在另一个目录（`F:\FedDIEG-main`），而且这个仓库 `F:\exp_FedDIEG` 里没有任何一份它的拷贝**（`git ls-files` 里没有 `FedDIEG.py`，历史里也只有 fast 版）。
- **因此三条验证实验测的不是论文的 FedDIEG。** 若要保留现有结论，必须：
  1. 在报告里把"仿真边界"从一句话（当前报告 §0.3 已有）升级为**对被削弱的那条通路的显式说明**；
  2. 或者重跑关键实验，用 A/B 版主程序（工作量：`val01` 需要把"参与序列"接到 A/B 版的 `sampled_clients` 上，`val02` 需要用 A/B 版的图更新替换，`val03` 同理）。

### 4.4 另外两个主程序侧的偏离（如果论文表格来自它们，必须交代）

1. **`server_lr` 15→1 的外推未在方法里描述。** `global_state[k] += server_lr * (avg - global)` 在前 80% 轮里把聚合更新放大 15 倍（`item_emb` 的有效学习率 ≈ 0.001×15 = 0.015）。这不是标准 FedAvg，且只对 `item_emb` 生效，属于"藏在代码里的调参"。
2. **个性化层的划分不一致。** `FedDIEG.py` 的 `is_personal` 里 `'forward_layers'` 能匹配 `forward_layers.*`，但**匹配不到 `forward_layernorms.*`**，而 `'attention'` 能匹配 `attention_layernorms.*`。结果是：**attention 之前的 LayerNorm 是个性化的，FFN 之前的 LayerNorm 是被聚合的**。`aligned` 版用 `"encoder.forward"`，两个 LayerNorm 都被个性化，修掉了这个不对称。**同一篇论文的两套主程序对"哪些参数上传"给出不同答案，复现者必然得到不同数字。**

## 5. 其余核实中发现的偏差（不改也能跑，但会影响结论）

### 5.1 摘要缓存：论文说"直接替换"，代码是动量 EMA

```python
# val01 L644-L649 / val02 L809-L814
momentum = min(max(cfg.feddieg_memory_momentum, 0.0), 0.99)     # 0.8
summary_bank[users] = seen * (momentum * summary_bank[users] + (1.0 - momentum) * new_memory) \
                    + (1.0 - seen) * new_memory
```

论文（L224–L238）写的是 `s̄_i^t = s_i^t, i ∈ C_t`（**直接覆盖**）。代码是 `0.8·旧 + 0.2·新`。这一步让"当前兴趣"永远只能进 20%，而且没有遗忘机制。当前阶段报告 §6 把"推荐性能损失来自摘要的累积方式"列为最关键结论之一——**这条结论恰好是代码偏离论文造成的**，必须在报告里明确，否则等于用"实现偏离"去证伪"算法假设"。

### 5.2 未参与客户端的边：论文说"异步更新"，代码里根本不更新

```python
# val01 L656-L659
if cfg.update_scope == "all":
    update_users = torch.nonzero(active_clients, ...)
else:
    update_users = sampled          # ← 默认：只有被抽样用户的行被重算
```

`val02`/`val03` 更是把 `update_users=sampled` 写死（`val02` L817）。论文（L285）明确写"对于已有历史缓存但本轮未参与的客户端，其边权由缓存摘要参与服务器端异步更新"，主程序 A/B 版也确实是**每轮对全部用户重算**。

后果：未参与者的邻居行**整行冻结**，它既不更新自己的图，也仍作为别人的候选。这把"陈旧"的影响放大了一条论文没有假设的通路。**`val01` 的 `--update-scope all` 只是事后补的开关，已产出的 36 次运行没有一次打开它**（`config.json` 里连这个字段都不存在，见 §5.6）。

### 5.3 `ρ` 的论文默认值 0.2 从未被验证实验覆盖

- 主程序：`FedDIEG.py` L56 `RHO = 0.2`；`aligned` L58 `feddieg_rho = 0.2`。
- 验证实验：`val01` L786 `--edge-ema default 0.80`；`val02` L998 `--rho default 0.80`，扫描 `0 / 0.5 / 0.8 / 0.95`；`val03` 用 `ρ0.00/0.50/0.80`。

也就是说：**实验二研究的是论文里根本不存在的 4 个 ρ 值**，而论文自己的 0.2 一次都没跑。这本身不是错误（任务书要求扫这几个值），但报告里不能把 ρ=0.8 的行为当成"FedDIEG 的默认行为"。结合 §3.4 的冻结机制，ρ≥0.5 的三条曲线测的是同一个状态，**结论应表述为"论文的 ρ=0.2 未验证；ρ≥0.5 时实现退化"**，而不是"ρ 越大适应越慢"。

### 5.4 ECR 有两种互不兼容的定义

| 实现 | 公式 | 值域 |
|---|---|---|
| `val01`/`val02`/`val03` | `len(old ^ new) / len(old ∪ new)`（对称差 / 并集，Jaccard 距离） | [0,1] |
| `FedDIEG.py` L442–L443 / `aligned` L1482 | `len(new − old) / K`（只有"新增边"比例） | [0,1] |

两者不可比：`new−old` 永远小于 `old ^ new`，所以主程序的 ECR 系统性偏小。**论文表里的"图变化率"和验证报告的 ECR 不是同一个量，不能放在一起叙述。**

### 5.5 `L_struct` 也是跨量纲 MSE

```python
# FedDIEG.py L204-L205（aligned L500、val01 L623-L632、val02 L788-L797 同构）
L_struct = F.mse_loss(current_delta_e, prev_edge_weights.detach())
```

`current_delta_e` 是 `clamp_min(cos)`（0–1），`prev_edge_weights` 在 `FedDIEG.py`/`aligned` 里是 **softmax 权重**（和为 1，典型 0.05），在 `val01`/`val02` 里是**归一化相对权重**。两者量纲不同。由于 `lambda_2 = 0.2`（`val01`/`val02`）或 `1e-5`（主程序），影响大小不同，但**"结构一致性"这一项在两个量纲之间做 MSE 本身就不是论文想表达的东西**。

### 5.6 已提交结果与当前脚本对不上

`val01` 的 `config.json`（`results/raw/movielens-1m/upload_only/p0.10/seed_42/`）里**没有 `update_scope` 和 `drift_sample_users` 两个字段**，而当前 `val01_run_staleness.py` 的 `Val01Config` 有这两个字段（L112–L113）。说明**现有 36 次运行是用更早一版脚本产出的**。两个字段默认关闭，行为大概率一致，但仓库里必须让"代码版本"和"结果版本"对齐（建议把 `config.json` 里写入 `git rev-parse HEAD` 与脚本 sha256）。

### 5.7 `graph_mix` 在两条实验里不一致

`val01` 用 `--feddieg-graph-mix default 0.05`（L775），`val02` 用 `graph_strength="paper"` 预设的 0.20（L111）。`val01` 自己已经发现 0.05 会把图效应淹掉（见 `val02` L105–L108 的注释）。**两条实验的"图影响强度"不同，跨实验比较 ECR/NDCG 时要交代。**

### 5.8 `val02` 的 `participation_rate` 默认 1.0

`val02` L1000 `default=1.0`，`val03` L1275 `default=1.0`。已产出的运行全部是 1.0（全员每轮参与）。这与论文 `C=0.1` 的设置不一致；对"固定 EMA × 兴趣漂移"这个单因子实验是可以接受的简化（去掉了参与率混淆），但报告里必须写明"本实验在全员参与条件下进行，不能与 C=0.1 的表格直接对比"。

## 6. 修复建议（按优先级）

### P0：先修实现缺陷，再谈结论

| 编号 | 修什么 | 最小改法 |
|---|---|---|
| **P0-1** | `val02`/`val03` 无效槽位写 `-1` | `new_ids = torch.where(keep, active[top_positions], torch.full_like(top_positions, -1))`，并让 `smooth_state` 同步只在 `keep` 位置保留 |
| **P0-2** | `scatter_` 的 `-1 → 0` 钳位 | 删掉 `clamp_min(0)`，改用 `torch.where` 或先 `masked_fill` 成合法索引再 scatter；或直接用 `prev[rows, cols] = ...` 的高级索引（`val01` 的 L276–L278 就是这么写的，没有这个 bug）。**必须先于 P0-1 完成** |
| **P0-3** | EMA 的 `prev` 量纲（`val01`） | 不要在 `prev` 里放归一化权重，而是像 `val02` 一样单独维护 `smooth_state`（原始 cos 量纲），归一化只用于喂给 GNN |
| **P0-4** | 阈值的作用对象 | 统一为"阈值只判存在性（作用在原始 cos 上），平滑量不参与阈值判定"——`val02` 的 `--graph-gate raw` 已经是这个思路，`val01` 没有 |

### P1：修"图冻结"这个结构性缺陷

| 编号 | 修什么 | 说明 |
|---|---|---|
| **P1-1** | 保留非 Top-K 边的 EMA 状态（或对新边做 warm start） | 两条路线：**(a) 论文忠实版**：日志域只对 Top-K 输出，但 EMA 状态放在 `N×K_candidate` 的候选池上（每轮按 cos 取 `K_candidate ≫ K` 个候选维护状态）；**(b) 工程版**：`new_edge_init="warm"`，并在报告里明确写"这不是论文公式，是让图能动的必要条件"。**必须二选一并说明**，否则 ρ 扫描没有意义 |

| **P1-3** | 补跑 ρ=0.2（论文默认） | 至少一条，否则论文的 FedDIEG 默认配置在验证实验里没有数据点 |
