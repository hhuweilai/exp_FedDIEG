### 3.1 旧（`val02_run_ema.py` 审计版本）

```python
model = FedDIEGModel(...)                      # 1 个模型
optimizer = optim.Adam(model.parameters())     # 1 个优化器
for round:
    for users in batched_indices(sampled, 512):
        loss.backward()

```

### 3.2 新（`feddieg_core/federated.py`）

```python
for user in sampled:                                   # ① 逐客户端
    local_state = {**global_state, **personal[user]}   # ② 同一轮所有客户端都从 θ_t 出发
    worker.load_state_dict(local_state)
    opt = Adam(worker.parameters(), lr=cfg.lr)         # ③ 客户端本地优化器
    for epoch in range(cfg.local_epochs):              # ④ 真正的本地 epoch
        neg = window.sample_negatives(user, rng)       #    负样本排除该用户历史
        loss = worker.compute_joint_loss(...)
        loss.backward(); opt.step()
    personal[user] = {个性化层}                         # ⑤ 个性化层留在本地
    sums += {共享层}                                    # ⑥ 共享层交给服务器
    upload_summary(user, s_u)                          # ⑦ 上传兴趣摘要
server: avg = sums / total_weight                       # ⑧ FedAvg
        item_emb: global += server_lr*(avg - global)    #    对齐 A/B 的 server_lr 外推
```

## 4. 与 A/B 主程序的逐项对齐

| 项目 | A/B 主程序 | 本实现 | 一致？ |
|---|---|---|---|
| 客户端采样 | `random.sample(range(N), m)`, `m=max(int(C*N),1)` | 同（`build_participation_schedule`） | ✅ 断言 C6 |
| 本地训练 | `E` 个 epoch、本地 `Adam(lr)`、训练后清空优化器状态 | 同 | ✅ 断言 C7 |
| 个性化层 | `is_feddieg_personal`：encoder 的 attention/FFN/LN + `W_proj` + `q_att` | 同（改成显式前缀，避免 A 版的不对称） | ✅ 断言 A1–A3 |
| 共享层 | `item_emb` / `pos_emb` / `W_gnn` / `W_g` | 同 | ✅ 断言 A2 |
| 聚合 | `sum/m`（uniform）；非 item_emb 直接取平均 | 同；另外可选 `--fedavg-weighting sample` | ✅ 断言 C1 |
| `item_emb` 外推 | `global += server_lr·(avg-global)`，15→1，`decay=int(rounds*0.8)` | 同 | ✅ |
| 模型结构 | SASRec（`item_emb*sqrt(d)`）+ 短期注意力池化 + `W_g(relu(Σw·W_gnn(h)))` | 同 | ✅ 断言 A4/A5 |
| 打分 | 最后位置与候选集内积，Top-10 | 同 | ✅ |
| 图更新范围 | 每轮对**全部**用户重算 | 默认 `all` | ✅ 断言 B9 |
| 图公式 | `e = ρe + (1-ρ)Δe`，Top-K，softmax | 同 | ✅ 断言 B5/B6 |

### 4.1 三处**刻意**的偏离（都有开关，可回退）

| 偏离 | 为什么 | 回退方式 |
|---|---|---|
| 图 EMA 状态存"候选池"而非只存 Top-K | 只存 Top-K 会让新边永远进不来（审计 §3.4 已证明这是实现缺陷而非算法设计） | `--graph-state topk` |
| `L_struct` 的目标用上一轮的 Δe，而不是上一轮的 softmax 边权 | A/B 版把 cos 量纲和 softmax 量纲做 MSE，语义不成立 | `--struct-target edge_weight` |
| 个性化参数按"A/B 的同一份初值 + 覆盖项"存储 | A/B 为所有客户端各存一份（arts_crafts 上约 11 GB）；本实现与 A/B **数值等价**，只是省内存 | 无需回退 |

### 4.2 一个必须知道的事实：旧实验的模型不是主程序的模型

旧 `exp_01_fast_gpu.FedDIEGModel` 比 A/B 主程序**多出**这些模块：
`graph_gate`、`graph_norm`、`tail_power` 位置加权、`confidence_power`、`agreement_power`、
`short_score_proj/gate/norm`、`score_local_mix`、`score_residual_mix`、`feddieg_graph_mix`。
A/B 主程序里**一个都没有**（`u_i = seq_emb + W_g(g_i)`，直接相加）。

所以修复后 **NDCG 的绝对水平会和旧结果差很多**（旧的图信号被四道衰减压到几乎为 0，
见第一阶段报告 §2.4）。这不是回归，是把模型换成了论文真正跑的那个。
旧的 `--graph-strength paper/strong`、`--graph-gate`、`--new-edge-init` 三个参数因此消失，
`--graph-mix`（默认 1.0）是唯一保留的图注入强度旋钮。

### 6.2 实测耗时（MovieLens-1m，真实模型 d=64 / 2 blocks / L=50）

| 环节 | CPU（24 线程） | 4060 Laptop 8 GB | **3090 24 GB（服务器）** |
|---|---|---|---|
| 单轮图更新（N=6040, K=20, pool=160） | 133 ms | 23 ms | 未单独测（占比 <1%） |
| 单轮训练（m=604，1 个本地 epoch） | 16.7 s（28 ms/客户端） | 5.88 s（9.7 ms/客户端） | **2.45 s（4.1 ms/客户端）** |
| 单用户评测 | ≈ 8 ms | 1.47 ms | **0.55 ms** |
| **一次完整运行**（600 轮 + 60 次全量评测） | ≈ 3.5 h | ≈ 70 min | **≈ 28 min** |

3090 那 28 分钟的构成：训练 24.5 min + 评测 3.3 min + 图更新 <0.3 min。

> 注意：这个负载是**延迟受限**的——每个客户端有独立编码器权重，一轮必然要做 m 次
> batch=1 的前向/反向，主要开销是 kernel launch 而不是 FLOPs。
> 实测 4060 Laptop → 3090 只快了 **2.4 倍**（不是按 FP16 算力比的 5–8 倍），
> 印证了这一点。所以别指望换 A100/4090 能线性加速。

因此预算建议：
* 用 `--device cuda`；有双卡就**两个臂并行**（单条只占约 600 MB 显存）；
* 压测方向时：`--rounds-per-window 60 --eval-every 20 --max-eval-users 2000`；
* `--participation-rate` 线性影响训练耗时，`--eval-every` / `--max-eval-users` 影响评测耗时。

**校准跑的实测预算**（`--rounds-per-window 40`、5 窗口 = 200 轮、`--max-eval-users 1200`）：
3090 上单条约 **8.5 分钟**（训练 200×2.45 s ≈ 8.2 min + 评测 20×0.7 s），
双卡并行两条 ≈ 9 分钟；4060 Laptop 上单条约 20 分钟。

## 7. 旧结果怎么办

`results/raw/` 下现有的是**旧实现**的产物（config.json 里没有 `core_version`）。
新代码跑同名目录会**覆盖**它们。脚本启动时会打印警告，例如：

```
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
注意：...\rho0.80\seed_42 里已有的是【旧实现】的结果
（config.json 没有 core_version 字段 = 旧版单模型仿真 + 有缺陷的动态图）。
本次运行会覆盖它。若想保留旧结果，请先手动改名/备份，例如：
  Rename-Item 'seed_42' 'seed_42_legacy'
```

建议先整体备份：

```powershell
# 把旧的 raw 结果整体改名（保留，不删）
Rename-Item exp_val_1026\exp01_staleness_participation\results\raw  exp_val_1026\exp01_staleness_participation\results\raw_legacy_fastsim
Rename-Item exp_val_1026\exp02_ema_interest_drift\results\raw          exp_val_1026\exp02_ema_interest_drift\results\raw_legacy_fastsim
Rename-Item exp_val_1026\exp03_transient_vs_sustained\results\raw      exp_val_1026\exp03_transient_vs_sustained\results\raw_legacy_fastsim
```

这样新结果写进全新的 `results/raw/`，聚合脚本也不会把两代数字混在一起
（第一阶段的报告文档也是基于旧数字写的，需要按审计 §8 的对照表重写相关表述）。

### 11.5 跨机器复现的口径（2026-11-05 已实测修订）

* **CPU ≠ CUDA，别混**：同 seed 下 CPU smoke 的 `avg_window_ndcg` 是 `0.0512`，
  CUDA 是 `0.0419`。原因是 dropout 掩码来自各设备自己的 RNG，不是 bug。
  同一组对照实验必须用同一种设备跑完。
* **CUDA → CUDA 可复现（已实测）**：4060 Laptop（torch 2.2.1+cu121）与
  3090（torch 2.15.0+cu132）同 seed 下四个指标**逐位一致**
  （`0.041944 / 0.098639 / 0.049803 / 0.146221`），真实规模探针 NDCG 都是 `0.0590`。
  换机器、换卡、升级 torch/CUDA 都不影响 —— dropout 掩码来自 philox RNG，
  序列由 seed 唯一决定。
* `--seed` 控制采样、初始化、负采样；两侧随机流一致。
* 结果目录里会写 `config.json`（含 `core_version`），合并跨机器结果前对一下这个字段。

### 11.6 本次为 CUDA 专门修掉的两处问题

| 位置 | 现象（只在 CUDA 上炸） | 修法 |
|---|---|---|
| `feddieg_core/graph.py::gather/neighbors/update` | 调用方传 CPU 索引张量（如 `window.active_users`）时，`self.ids[users]` 会报 device 不一致 | 三个入口统一 `users.to(self.device)` |
| `feddieg_core/bench_graph.py` | 用 CPU `Generator` 配 `device=cuda` 造随机数会报 `Expected a 'cuda' device type for generator` | 先造 CPU 张量再 `.to(device)` |
